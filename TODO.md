Found two bugs that each *looked* like a second indicator: the sweep **leaked on permanently** (`showBusy` incremented unconditionally, `hideBusy` decremented only `if(_busy)`, so two overlapping mutations left the 2px bar lit for the session with nothing running), and it sat under the panel for the whole of every counted job. The top sweep stays as the fallback for reads with nowhere of their own — facets, a card's data sheet, boot — since removing it puts those back to no indication at all
- [x] **Downloading shows a real bar, and it was a real defect** — `/api/fetch` spends one CLI call per *described* card, so four picked cards were four jobs of one item; one item is not `positional`, so it drew a sweep with a note flickering between ids. `webui._Counted` keeps the count on the **request** (the thing that knows the total) and the inner calls run unwatched. Measured `0 of 4` → `1 of 4` at 25%, `~1.0s left`. The undescribed batch path is untouched — `cli._each` already counted it

## Pipeline defaults

- [x] Grade defaults to identity — a look proxdex invented for every card is the same mistake as an invented print profile
- [x] Upscale factor derived per card from `[tools] upscayl_min_dpi` (1000, which reproduces `base3-4`'s 2508×3504 exactly), not a fixed 2×+double that scattered results from 592 to 1011 dpi. `--scale` overrides; 0 turns it off

A _target_ with nearest-by-ratio was tried and was worse: every target from 1050-1450 gave byte-identical output, so the setting looked precise and was not
- [x] `config prune` removes keys nothing reads, with their comments — the real library carried 7 from the deleted auto-detector and the deleted grade white-balance, and both surfaces called them ignored without offering to remove them
- [x] **Decided:** the factor ladder stays coarse. Deriving `double` as well as `scale` would give 1/2/3/4/9/16 instead of 1/4/9/16, but `double` is a _quality_ knob ("sharper on small sources"), so it stays the user's choice — and `--scale`/`--no-double` are there per run. The cost is a step: a 600px master goes to 5400px to clear 1000 dpi
- [x] **Decided, not fixable mechanically:** a real library's `[print]` still carries prose about the deleted `none|paper|foil` presets, sitting above _live_ keys. `config prune` removes dead keys and the comments belonging to them; a stale comment beside a key that still exists is indistinguishable from a good one, so it is a hand edit or nothing

## The border fill

- [x] **The border step is two steps.** One: place the marks, Run, defaults — and the reading is recorded (`.marks-bordered[_f2]`), so `border` with no `--inner-*` repeats it. Two: on a done step, cardbleed's 13 settings sit under the step's own controls and changing one **re-borders the card there and then**, invalidating the later stages as any re-run does. `border --tune KEY=VALUE` / `--tune-help` / `--no-tune` on the CLI; the tuning is kept per card in `.tune-bordered[_f2]`, non-defaults only
- [x] Everything closed is an enum (`KnobId`, `FillMode`, `Halo`, `EdgeFill`) and everything numeric a `Range`; a knob is a set **or** a range, never both, so `_coerce` has no unvalidated path. A choice's values come from its enum rather than being restated, and `Tuning` is keyed by `KnobId`
- [x] The **preview was built and removed** — a picture of a fit you have not made has to be invalidated when the marks move, explained as not-the-real-thing and kept in step with both; re-running the real verb has none of those problems. It also went at the bottom of the panel, 795px down a 1000px viewport
- [x] The cascade confirm is gone (`okCascade`) — it stood between every attempt at tuning a border, and the cascade is _reported_ instead. Deletes still ask
- [x] proxdex validates every knob **because cardbleed does not** — it accepts `jittter=0.1`, `mode="nonsense"` and `jitter="lots"` in silence and uses its defaults. `tests/test_bleed_tuning.py` also holds the knob list against `cardbleed.Params`, so a renamed field fails the suite rather than becoming an ignored override
- [x] **A fill setting only does anything where border is actually invented**, and both the CLI and the panel now say when it is not: marks on the spec give extensions of ~1e-13px and all three fill methods produce a byte-identical file. Nearly shipped the other way — three modes were compared by eye on a scaled screenshot and read as different when they were the same bytes
- [x] Also measured: on a **perfectly flat** border the method makes no difference either, so a synthetic flat card is the wrong thing to test a fill with — grain is what the methods disagree about
- [x] **More than one border can apply to a set, and the user picks** — `specs.Candidate` / `Resolution.alternatives`, collected in the _same_ walk `resolve` already made (a second pass would be two answers to one question). A second whole-set rule is no longer deleted as unreachable: it is reachable by being picked. `border` names the choice every run, `frames` grows an **Or** column, the align panel lists them as buttons that pin, and the offer is symmetric so you can switch back. Not a `frames check` fault — two measured answers is a question with two good answers
- [x] **The align sidebar is a label, not a lesson** — the four editable `%` fields are gone (nobody types a border inset; it is read off the picture, and the value is on the loupe and in the readout), the prose is one line per state, and every step option's `help` moved to the row's `title` like the fill knobs already did. 605px → 505px on a done border step
- [ ] `border`'s readout can be **1px off the file it wrote** — a 554×769 source reported `fit → 554×776px` and the PNG on disk is 555×777 (np-9 at 747×1040 matched exactly). Cosmetic: the aspect is exactly 63.5:88.9 and every border edge lands on the spec, so it is the printed *number* that rounds, not the geometry. Likely `solve_fit`'s trim vs what cardbleed writes
- [x] **The ex era's two borders now cover five sets** — `ex1` Ruby & Sapphire, `ex2` Sandstorm, `ex3` Dragon, `ex4` Team Magma vs Team Aqua and `np`, 2003-07 to 2004-03: each printed cards with the e-Reader strip along the bottom *and* cards with a plain square border, so both `pokemon-ecard-ex` and `pokemon-ex-plain` resolve as candidates and a person picks. `ex5` (Hidden Legends) onward deliberately still refuses. Forced a real fix: **`Baseline.sets` is exact ids, not prefixes** — no prefix covers `ex1` without also claiming `ex10`–`ex16` (2005-07, never read), and `"base"` was already claiming `basep` silently. `basep` stays on `pokemon-wotc` (dropping it would stop a card that borders today) and is recorded as **inherited, not measured**
- [x] **A card with no measured spec could not be aligned at all** — the escape hatch (`border --frame`, i.e. the step's Frame setting) was unreachable in the UI on exactly the cards that need it, every Pokémon printing past the e-Reader era. Four faults: `renderAlignPanel` read `g.frameless` on a **null** guide and threw, taking the panel *and* the `Align the border` button with it; `whyThisSpec` returned '' when nothing resolved, so the one card needing an explanation got silence; a step setting lived only in the DOM, so clicking `Align the border` (a re-render) reverted the Frame to Automatic — now `stepMem`, keyed by card/side/step so an override cannot leak onto the next card; and `onSetting` returned early with the layer down, so a **done** step ignored the Frame entirely. Verified end to end: choose → align → run → `Keep`, and the card resolves via pin with `frames check` clean
- [x] **Picking between two borders is a radio group now** — it was a via chip beside a mono id plus a row of same-weight buttons for the others, which showed neither which spec was in force nor what it was *called* (the buttons had the names, the selected one had only its id). One row per applicable spec, each with its **four border widths** (`3.12 / 3.24 / 6.76 / 7.16` vs `9.10 / 2.61 / 6.76 / 7.16` is the difference at a glance; `Candidate.json` serves `mm`, and `FrameGuide.json` deliberately does not since it is also the on-disk format), the whole row as the hit area, arrow-key navigation, the accent on the selected row as everywhere else in the app, **sorted by id** so the row you click does not jump to the top, and no selection styling at all when only one applies
- [ ] The align panel cannot name **what a done master was actually fitted to** — `.fit-bordered` records it and `/api/frame` does not serve it, so a card whose printing resolves to nothing shows `no frame spec measured` over a master that was bordered against a real spec, and picking a different candidate on a bordered card says nothing about the master going stale (`doctor`'s `stale-spec` knows)
- [ ] The border step's **Frame** dropdown offers every spec of **both games** (`mtg-vanguard` on a Pokémon card) and labels them by bare id rather than name — `/api/frame` already filters by game (`reg.choices(card.game)`), the step schema from `/api/meta` does not
- [x] **A square promo border** — `pokemon-ex-plain`, one hand reading (554×769, **23px on all four edges**), covering set `np` alongside the strip spec: the promos printed without an e-Reader dot code have nothing to be asymmetric about. Top 2.991% / sides 4.152% — 2.66 / 2.64mm, the thinnest Pokémon spec and nearer `mtg-m15` than WOTC. Square in mm as well as px, which is a separate fact (different fractions, one width) — the 0.02mm gap is the file's aspect being 0.85% wide of the card's. Both `np` frames resolve as candidates since nothing in the metadata says which a card is; `pokemon-ecard-ex` is the default on weight of evidence (two cards vs one), **not** a claim about which is commoner
- [x] **The ex era's strip moved** — `pokemon-ecard-ex`, from two hand readings (747×1040: L32 R27 T39 B71; 455×642: L20 R17 T23 B43), covering set `np` only. The e-Reader dot code runs along the **bottom alone** (6.01mm) with three ordinary edges (top 3.26 / left 2.76 / right 2.33mm), so it is a different _shape_ rather than a renumbered `pokemon-ecard` — that spec would have asked 7.16mm of left border where the card has 2.76. Stored as the per-edge average; the two cards agree to 0.17pp across a 1.64× scale gap and the stated totals land exactly on three of four (the fourth is a 1px slip, 0.14mm). **Left and right not collapsed** — both cards read left wider by the same 0.67pp, which a cutting error does not do. Keyed to `np` alone: the strip ran on into ex, but that has not been read
- [x] **A second e-Card frame** — `pokemon-ecard-deep-top`, from a third hand reading (468×650: L52 R20 T67 B49). Left and bottom agree with `pokemon-ecard` to 0.158pp / 0.070pp so they are **shared**; top and right are re-derived to hold the reading's _sums_ (a crop shifts opposite edges against each other, so a pair's sum survives what neither edge does), giving top 10.238% / right 4.116%. `right` not substituted — 0.53mm out, 7x the first two cards' agreement. `frames.baselines` returns a tuple so both ship for `ecard1`–`ecard3` and the candidate picker chooses per card. Which printing has the deeper top is **not** recorded, because it was not read
- [ ] A Trainer or Energy e-Card has **nothing to place the top mark against** — its frame is the same yellow as its border, so the border's inner edge is invisible (unlike a Pokémon card, whose art panel starts at ~21px of 825). An alignment problem, not a spec one; the single measured `pokemon-ecard` inset stands
- [ ] `doctor` knows nothing about a stored tuning. A master filled with settings that are no longer on the card (or a `.tune-bordered` naming a knob a later cardbleed dropped) is invisible — the same shape of gap `stale-spec` was added for

## Speed and waiting

- [x] **Browse was slow because of provider art, not JSON** — the set list answers in 9ms warm, then the page pulled 174 logo PNGs at ~139 KB each (24.7 MB) into a slot 2.25rem tall, and a 60-card page pulled 45 MB of full-size scans into 190px tiles, all of it again next visit. `art.py` + `/api/art`: fetched once, resized to the size it is drawn at, kept in the cache dir, served immutable. **4.17 MB → 215 KB** for the first screenful of logos, **45.1 MB → 2.10 MB** for a card page, **0 bytes / 0ms** on the second visit
- [x] A picture host is not an API (`net.CDN_INTERVAL`) — held at the 100ms Scryfall asks of _its API_, one screen of 174 logos would have been 17s of pure waiting. `get` takes an `interval=` and the limit on art reads is the pool that issues them
- [x] The host is checked against a list, full-host match — a lookalike domain and the allowed host as a path segment are both refused, and pinned. An open fetcher is a hole even on localhost
- [x] **Waiting has a shape** — `progress.py`, a file channel (`$PROXDEX_PROGRESS`) that is a no-op for a terminal user, so the CLI's output is byte-for-byte what it was and nothing is parsed out of human text. `_each` reports items, `sheet._pages_to_pdf` reports pages; `/api/progress` reads it while `run_cli` is still blocking. Measured: a 47s duplex imposition went from one spinner to `3 of 4 · page 3`
- [x] An unknown total stays unknown — one card through Upscayl has no fraction to be had, so it gets a sweep, an elapsed clock and `~41s typical` (the median of _your own_ last runs, labelled). Never a bar position: a fraction nobody measured sitting at 90% is the same lie as a border nobody measured
- [x] **A count of one is not a position** (`Report.positional`) — one card through Upscayl or grade is a real count of 1 whose bar could only read 0% and then vanish, which is what "the bar is empty and then it's done" was. Below two items a reader falls back to the sweep, the clock and the typical; the rule is on `Report` because both readers need the same one
- [x] **An item names itself** — `cli._each` took `str(item)`, so the three verbs whose items are `Card`s put `Card(id='ecard3-141', dir=PosixPath('/Users/…` in the panel as the note _and_ in `_last_failed`, where a retry needs a bare id. `name` is now a required parameter: a forgotten one is a type error
- [x] **`~14s left`, measured** (`Report.remaining`) — the command's own elapsed over the items it really finished, timed from when the _counting_ began (`Report.started`) rather than process launch, which was charging 5.2s of interpreter startup to the first page. Silent before the first item, at a total of one, and **once the count is complete**: `sheet` embeds the PDF after its last page, and `0s left` under a full bar through that is the spinner-that-knows-nothing with more confidence
- [x] Only runs the remembered estimate is _shown_ for are recorded, so one card through Upscayl and forty of them stop pooling into a median describing neither; well past it the panel says `longer than usual`
- [x] A wait too short to be one gets no panel — held back 320ms while the top sweep acknowledges the click, so a 20ms skip or config set no longer flashes a modal. The note is one line, truncated, full text on its `title`
- [x] `--clear-cache` clears _both_ kinds — `net._CACHED` is one list, or a second kind of cached thing becomes quietly unclearable. `where` counts the pictures held
- [x] Skeleton plates on the browse and search pictures, which had none: the tiles sat empty rather than loading
- [x] **A Pokémon tile takes the provider's own small scan** (`[sources] scrydex_thumb_url`, `/small`) — 245px and ~30 KB against `/large`'s 825 KB. The art cache could shrink what the _browser_ pulled but not the fetch that fills it, so the first visit stayed slow: a cold 60-card page went **3.49s → 0.72s**. A separate `SearchResult.thumb_url` rather than a suffix swapped at the point of use, so nothing downstream can file a 245px master — which would border, upscale, grade and impose without complaint and be wrong only on paper
- [x] **MTG too** — `image_uris.normal` (488×680) for the tile, `png` still what gets filed. The mechanism differs because the providers do: Pokémon's variant is a URL template (configurable), Scryfall's is a key on the card's own response (`_MTG_THUMB_KEYS`, not a setting — there is no template to point). Measured over 32 cards in four sets: `png` 1657 KB median (range **331-2206** — an old scan is far heavier than a modern one), `normal` 120 KB (range 78-146). ~14x at the median, 3x on the lightest set, and the real win is a **flat** cost: a page of Alpha now costs what a page of Aetherdrift costs, where before it was 102 MB against 23. A cold 60-card MTG page is 1.11s

- [x] **Pokémon name search was one term per word, which threw the words away** — a space separates *terms*, so `Moo Moo` became `name:*Moo* name:*Moo*`: two identical substring tests, exactly equivalent to searching `Moo`, answering Amoonguss / Bloodmoon Ursaluna / Roaring Moon with no Moo Moo Milk in sight. Joined into `name:*Moo*Moo*` it returns the five that exist — and the wildcard where a space was typed is also what matches **Moo-Moo Milk** (Neo) *and* **Moomoo Milk** (HeartGold), neither of which `name:"Moo Moo"` finds at all (0 results, measured). Scryfall stays per-word; it already ranks correctly and is order-insensitive

- [x] **An empty search names what emptied it** — `state.find` survives paging, a screen switch and a reload, so the filter that killed a query is usually one set on another screen a while ago: browse a set, switch to Search, type a name, and the set is still narrowing. `Nothing matched. Try fewer filters` was true and useless; it now reads `Nothing in Pokémon matched Moo Moo with set base1` and carries a **Drop it** button
- [x] Scryfall stays **per-word**, measured rather than assumed: the phrase form `name:"Serra Angel"` is more precise (1 hit vs 2) but `name:"kiki jiki"` returns **0** where `name:"Kiki" name:"Jiki"` finds Kiki-Jiki — it breaks on the hyphens Magic names carry, which is the same hazard the Pokémon join fixes. Its one real flaw is that repeated words collapse (`Moo Moo` = `Moo`, 138 cards), and no Scryfall spelling avoids that without the hyphen regression

## Robustness

- [x] **Retries are chosen by what giving up costs** — `net.get(attempts=)`, default 4 for reads that draw a screen, `PATIENT_ATTEMPTS` = 7 for a card's metadata and its image. Takes the loss from ~1 card in 16 to ~1 in 1000 at the measured 500 rate; the 23.5s worst case is spent only when a host really is down, and a stale cache entry is still served before it raises
- [x] **A card is filed from metadata the caller already read**, so the UI's Add no longer re-asks for the name/set/rarity it had just drawn — `fetch --name/--set-name/--rarity/--subtypes`, `FetchBody.known`, one CLI call per described card. Pokémon only: a Magic image URL is a uuid path only Scryfall's answer carries. Safe _because_ `download` refuses the placeholder — skipping the lookup skips the proof the id exists
- [x] A Pokémon search row now carries the traits a lookup does (`subtypes` added to `select`, 5% of response size) — a card added from a search used to get **no** traits while the same card via `fetch` got rarity and subtypes, so a subtype rule answered differently depending on which verb filed it
- [x] **A failed download no longer leaves a phantom card.** The folder plus `.game`/`.layout` with no image counted in `ls`, drew a contact-sheet tile and read "4 of 5 originals" — a card that could never become ready. `_acquire` rolls back a folder it created when nothing landed; an existing card whose re-download fails is left alone
- [x] **A fetch failure names the card, and `fetch` prints the retry.** `NetworkError`'s message is the _host_, so a batch reported `SKIPPED api.pokemontcg.io` and you could not tell which card to run again; `_get` takes a `what=` now and `fetch` ends with a paste-able `proxdex fetch --game … <ids>` for exactly what missed
- [x] **The image host answers 200 with a placeholder for an id it does not have** (`base1-999`, `zzzz-1` → the same grey file), which is why a Pokémon fetch must resolve the id against the metadata API even though the image URL is derivable from the id alone. `sources.is_placeholder` (640×892, palette mode — no real scan is either) refuses it instead of filing a grey rectangle that every later stage would happily print
